# Как звать скиллы

В проекте лежат 105 скиллов. Почти все спят, и это правильно. Вот как разбудить нужный.

## Одно правило

Хочешь позвать скилл, напиши в чат слэш и его имя:

```
/impeccable
```

Ничего устанавливать и включать не надо. Скилл загрузится целиком в момент вызова и будет работать до конца разговора.

## Как это выглядит в разговоре

Два способа, оба рабочие.

**Сначала позвать, потом просить:**

```
Ты:      /redaktura
Claude:  Пришли текст, скажи, кто читатель и где он будет жить.
Ты:      Вот черновик письма клиентам...
```

**Всё сразу одним сообщением:**

```
Ты:      /banana нарисуй обложку для статьи про семейный бюджет
```

Второй способ обычно быстрее.

## Почему они спят

Если бы все 105 работали одновременно, Claude при каждом запуске читал бы 105 описаний. Это занимает место, которое нужнее для твоей задачи. Плюс восемь дизайнерских скиллов начали бы спорить, кому браться за работу.

Поэтому им проставлено поле `disable-model-invocation: true`. Смысл поля: сам не лезь, но по имени отзывайся.

**Спящий не значит выключенный.** Скилл целиком лежит в проекте и работает как раньше. Единственная разница: Claude не возьмёт его по своей инициативе.

Семь скиллов не спят, потому что срабатывают на обычные просьбы без команд: шесть русских редакторских плюс `stop-slop` для английского.

## Как добавлять новые скиллы

Просто пришли ссылку на репозиторий, команду установки или файл. Дальше работает `/add-skill`, звать его отдельно не нужно, он срабатывает сам.

Что произойдёт:

**1. Проверю на дубль.** Ответ будет одним из трёх, а не да или нет:

- *Точно такой есть* — не ставим, скажу, где лежит
- *Похожий есть* — покажу, чем перекрывается и в чём разница, решаешь ты
- *Такого нет* — идём дальше

**2. Посмотрю, что внутри.** Объём, только Markdown или есть исполняемый код, есть ли хуки, нужен ли ключ или доступ к закрытым доменам. Скажу прямо, если внутри что-то запускается.

**3. Поставлю в спящем режиме,** чтобы контекст не рос.

**4. Добавлю строку в шпаргалку** выше, чтобы через неделю не искать по истории.

**5. Закоммичу** отдельным коммитом на каждый скилл.

Ставим по одному и под задачу. Скилл, поставленный впрок, обычно не вызывается ни разу.

## Если хочешь, чтобы срабатывал сам

Убрать из файла одну строку:

```bash
sed -i '/^disable-model-invocation: true$/d' .claude/skills/post/SKILL.md
```

Вернуть обратно: дописать эту же строку в блок между `---` в начале файла. Изменение заработает со следующего запуска.

## Плагины устроены иначе

Плагин это набор скиллов целиком, и у него общий выключатель. Выключенный плагин не даёт ничего, позвать его по имени не выйдет.

| Действие | Команда в терминале |
|---|---|
| Посмотреть список | `claude plugin list` |
| Включить | `claude plugin enable ИМЯ@claude-settings` |
| Выключить | `claude plugin disable ИМЯ@claude-settings` |

После включения набери в чате `/reload-plugins`, иначе изменение подхватится только в новом разговоре.

Сейчас работают два плагина.

`intelligent-compact` следит, чтобы при сжатии длинного разговора не потерялись пути к файлам и причины поломок.

`ponytail` перед написанием кода проходит лесенку простоты — не нужно вовсе, уже есть в проекте, есть в стандартной библиотеке, одна строка, и только потом минимум необходимого. Не трогает существующий код, не блокирует запись файлов: перед стартом сессии подкладывает инструкцию, дальше просто отслеживает режим. Три интенсивности — `lite`, `full` (по умолчанию), `ultra`, переключаются словами в чате: «ponytail ultra», «ponytail lite». Выключить одной фразой: «ponytail off».

Остальные тридцать выключены. Включай под задачу: `python-skills` для Python, `stripe-skills` для оплаты, `github-dev` для пул-реквестов.

## Субагенты и коробка

Субагент это отдельный исполнитель, которому можно поручить кусок работы. От скилла отличается одним важным свойством: **спать он не умеет**. Всё, что лежит в `.claude/agents/`, грузится в контекст всегда, выключателя нет.

Поэтому в работе их мало, восемь штук: `debugger`, `python-pro`, `fastapi-developer` плюс пять своих от `impeccable` и `banana`.

Ещё 155 лежат на хранении в папке `agents-library/`. Claude туда не заглядывает, контекст они не тратят. Достать нужного:

```bash
cp agents-library/02-language-specialists/sql-pro.md .claude/agents/
```

Подробности и список категорий в [agents-library/README.md](agents-library/README.md).

## Если что-то пошло не так

**Написал `/impeccable`, ничего не произошло.** Проверь, что сообщение началось со слэша без пробела перед ним, и что имя без опечаток. Набери один слэш и посмотри подсказку.

**В подсказке нет нужного имени.** Разговор идёт не в том проекте либо не на той ветке. Скиллы живут в репозитории home-accounting, в ветке main.

**Скилл ответил, но результат не тот.** Опиши задачу подробнее в том же сообщении. Скиллы это инструкции, а не кнопки.

**Позвал два скилла, они мешают друг другу.** Так бывает у дизайнерских, у них разные мнения о хорошем интерфейсе. Зови по одному за раз.

**Просит ключ или не может выйти в интернет.** Часть скиллов ходит во внешние сервисы. Скиллу `/banana` нужен ключ Google, некоторым плагинам нужен Docker или облачный вход.

## Клонирование сайтов

`/clone-website` уже включён у тебя лично на claude.ai — работает в любой сессии, ничего ставить не надо. Разбирает сайт по кускам и пересобирает его как код: экранные снимки, точные CSS-значения, поведение при скролле и наведении, реальный текст и картинки, а не заглушки.

Но сам он ничего не создаёт с нуля. Ему нужен готовый каркас — Next.js, shadcn/ui, Tailwind v4 — уже лежащий в репозитории, где его запускают. Без каркаса он остановится и попросит подготовить проект сначала.

Когда появится конкретный сайт для клонирования:

1. Заведи новый репозиторий из шаблона [JCodesMore/ai-website-cloner-template](https://github.com/JCodesMore/ai-website-cloner-template) — кнопка **Use this template** на странице репозитория, либо `gh repo create ИМЯ --template JCodesMore/ai-website-cloner-template`.
2. Открой сессию на нём.
3. Позови `/clone-website https://адрес-сайта`.

Шаблон уже несёт файл скилла под шесть разных сред (`.claude`, `.codex`, `.cline`, `.kiro`, `.roo`, `.github`), так что подойдёт не только для Claude Code.

Отдельный репозиторий заводим только в момент реальной задачи, не заранее: пустой проект под гипотетический будущий сайт — то же самое, что скилл про запас, только для репозиториев.

## Хранилище заметок Obsidian

`AgriciDaniel/claude-obsidian` — плагин для хранилищ Obsidian с указанием источников: заводит или забирает под управление хранилище, ведёт восстанавливаемые операции, детерминированный поиск, журнал происхождения записей. Проверен: только два хука (`SessionStart`, `Stop`), без фонового процесса и без MCP-сервера. Сеть трогает в двух местах, и оба по явному согласию — вызов Anthropic API для контекстуализации кусков текста при индексации (свой ключ, не автоматически) и локальный Ollama на `127.0.0.1` для поиска по смыслу. Никакой телеметрии.

Не устанавливаем отсюда. Хранилища заметок живут на твоей машине — эта сессия работает в облачном контейнере и до `C:\` не достаёт, ни установить плагин так, чтобы он видел твои файлы, ни запустить его против них отсюда нельзя.

Когда будешь ставить сама, на своей машине, в Claude Code с открытым хранилищем:

```
/plugin marketplace add AgriciDaniel/claude-obsidian
/plugin install claude-obsidian@agricidaniel-claude-obsidian
/claude-obsidian:wiki
```

Стартовать пустым не обязательно: плагин умеет забрать под управление уже существующее хранилище с заметками — «explicit vault adoption» в его описании.

Держи заметки отдельно от кода. Хранилище внутри рабочей папки проекта — то смешение, от которого мы вообще отталкивались весь день. Отдельная папка, отдельное хранилище.

## Плагины в запасе

`small-business@knowledge-work-plugins` — официальный плагин Anthropic, 31 скилл под операционку малого бизнеса: закрытие месяца, просроченные счета, зарплаты, ревью договоров, приоритизация лидов, найм. Установлен, но выключен: `claude plugin enable small-business@knowledge-work-plugins` и `/reload-plugins`.

Каждый скилл там завязан на внешний сервис — QuickBooks, PayPal, HubSpot, Canva, DocuSign, Stripe, Square, Slack, все требуют своего платного аккаунта и авторизации. Пока ни один из них не подключён, включать смысла нет: почти всё упрётся в отсутствие данных.

Внутри плагина свой `content-strategy` — не дубль установленного, а завязанный на продажи из PayPal и QuickBooks. Если решишь включить плагин, у нас окажутся два скилла с одним именем; тогда переименуй один из них перед включением.

`claudex-loop@claudex-loop` — план проверяет одна модель, строит другая, готовый код инспектирует третий проход, независимо. Внутри четыре скилла: `claudex-loop` (полный цикл), `claudex-route` (лёгкий совет «кому отдать задачу», работает и без остального), `codex-build`, `codex-review`. Проверен: 168 КБ, ни хуков, ни MCP-сервера, единственный скрипт вызывает `git` и выбранный CLI обычным подпроцессом с таймаутом. Включить: `claude plugin enable claudex-loop@claudex-loop` и `/reload-plugins`.

Держит на Codex CLI — автономном агенте от OpenAI, том же классе инструмента, что Claude Code, только не установлен здесь и, судя по всему, нигде. Без него работает только `claudex-route` в режиме совета, сама передача задачи — нет. Пересекается по смыслу с уже зарегистрированным `codex-advisor@claude-settings` (тоже выключен): оба зовут Codex вторым мнением, `claudex-loop` — полным циклом с журналом решений, `codex-advisor` — разовым советом. Ставить оба смысла нет.

## Ключи

Ключи API в репозиторий не кладём. В облачных сессиях они живут в поле Environment variables в настройках окружения, локально задаются через `claude mcp add --env`.
