# Как звать скиллы

В проекте лежат 105 скиллов. Почти все спят, и это правильно. Вот как разбудить нужный.

## Одно правило

Хочешь позвать скилл, напиши в чат слэш и его имя:

```
/impeccable
```

Ничего устанавливать и включать не надо. Скилл загрузится целиком в момент вызова и будет работать до конца разговора.

## Как это выглядит в разговоре

Два способа, оба рабочие.

**Сначала позвать, потом просить:**

```
Ты:      /redaktura
Claude:  Пришли текст, скажи, кто читатель и где он будет жить.
Ты:      Вот черновик письма клиентам...
```

**Всё сразу одним сообщением:**

```
Ты:      /banana нарисуй обложку для статьи про семейный бюджет
```

Второй способ обычно быстрее.

## Почему они спят

Если бы все 105 работали одновременно, Claude при каждом запуске читал бы 105 описаний. Это занимает место, которое нужнее для твоей задачи. Плюс восемь дизайнерских скиллов начали бы спорить, кому браться за работу.

Поэтому им проставлено поле `disable-model-invocation: true`. Смысл поля: сам не лезь, но по имени отзывайся.

**Спящий не значит выключенный.** Скилл целиком лежит в проекте и работает как раньше. Единственная разница: Claude не возьмёт его по своей инициативе.

Семь скиллов не спят, потому что срабатывают на обычные просьбы без команд: шесть русских редакторских плюс `stop-slop` для английского.

## Как добавлять новые скиллы

Просто пришли ссылку на репозиторий, команду установки или файл. Дальше работает `/add-skill`, звать его отдельно не нужно, он срабатывает сам.

Что произойдёт:

**1. Проверю на дубль.** Ответ будет одним из трёх, а не да или нет:

- *Точно такой есть* — не ставим, скажу, где лежит
- *Похожий есть* — покажу, чем перекрывается и в чём разница, решаешь ты
- *Такого нет* — идём дальше

**2. Посмотрю, что внутри.** Объём, только Markdown или есть исполняемый код, есть ли хуки, нужен ли ключ или доступ к закрытым доменам. Скажу прямо, если внутри что-то запускается.

**3. Поставлю в спящем режиме,** чтобы контекст не рос.

**4. Добавлю строку в шпаргалку** выше, чтобы через неделю не искать по истории.

**5. Закоммичу** отдельным коммитом на каждый скилл.

Ставим по одному и под задачу. Скилл, поставленный впрок, обычно не вызывается ни разу.

## Если хочешь, чтобы срабатывал сам

Убрать из файла одну строку:

```bash
sed -i '/^disable-model-invocation: true$/d' .claude/skills/post/SKILL.md
```

Вернуть обратно: дописать эту же строку в блок между `---` в начале файла. Изменение заработает со следующего запуска.

## Плагины устроены иначе

Плагин это набор скиллов целиком, и у него общий выключатель. Выключенный плагин не даёт ничего, позвать его по имени не выйдет.

| Действие | Команда в терминале |
|---|---|
| Посмотреть список | `claude plugin list` |
| Включить | `claude plugin enable ИМЯ@claude-settings` |
| Выключить | `claude plugin disable ИМЯ@claude-settings` |

После включения набери в чате `/reload-plugins`, иначе изменение подхватится только в новом разговоре.

Сейчас работает один плагин, `intelligent-compact`. Он следит, чтобы при сжатии длинного разговора не потерялись пути к файлам и причины поломок. Остальной тридцать один выключен. Включай под задачу: `python-skills` для Python, `stripe-skills` для оплаты, `github-dev` для пул-реквестов.

## Если что-то пошло не так

**Написал `/impeccable`, ничего не произошло.** Проверь, что сообщение началось со слэша без пробела перед ним, и что имя без опечаток. Набери один слэш и посмотри подсказку.

**В подсказке нет нужного имени.** Разговор идёт не в том проекте либо не на той ветке. Скиллы живут в репозитории home-accounting, в ветке main.

**Скилл ответил, но результат не тот.** Опиши задачу подробнее в том же сообщении. Скиллы это инструкции, а не кнопки.

**Позвал два скилла, они мешают друг другу.** Так бывает у дизайнерских, у них разные мнения о хорошем интерфейсе. Зови по одному за раз.

**Просит ключ или не может выйти в интернет.** Часть скиллов ходит во внешние сервисы. Скиллу `/banana` нужен ключ Google, некоторым плагинам нужен Docker или облачный вход.

# Техническая часть

## Что где лежит

```
.claude/skills/        скиллы (89 симлинков в .agents/skills плюс свои папки)
.claude/agents/        субагенты
.claude/settings.json  маркетплейс и список плагинов
.mcp.json              MCP-серверы проекта
skills-lock.json       источники и хеши установленных скиллов
```

## Механизм активации

| Настройка в `SKILL.md` | Вызываешь ты | Вызывает Claude | В контексте |

| нет поля | да | да | описание всегда |
| `disable-model-invocation: true` | да | нет | ничего |
| `user-invocable: false` | нет | да | описание всегда |

## Чего не стоит включать в облачной сессии

| Плагин | Причина |
|---|---|
| `azure-tools`, `gcloud-tools` | нужна облачная авторизация |
| `paper-search-tools` | нужен Docker |
| `tavily-tools` | нужен API-ключ |
| `ultralytics-dev`, `ultralytics-branding` | внутренние плагины про YOLO |
| `humanize` | хук запрещает длинное тире, ломает русскую типографику |
| `claude-telemetry-hooks` | хук на каждое событие сессии |

Отдельно про `/booklet`. Ставить его можно, звать тоже, но целиком маршрут отсюда не пройдёт: фаза с картинками идёт через Replicate, а домен закрыт политикой окружения. Нужен `REPLICATE_API_TOKEN` и оплата, плюс `weasyprint` и `ghostscript` в системе. Локально работает полностью. И замени пресет `univerus` на свой `brand.yaml`, там сейчас чужой фирменный стиль.

## Ключи

Ключи API в репозиторий не кладём. В облачных сессиях они живут в поле Environment variables в настройках окружения, локально задаются через `claude mcp add --env`.
