# Дизайн-гайд PDF

Цель: создавать лид-магниты, которые выглядят как брендированные мини-журналы, но остаются легко читаемыми с телефона.

## Портативность

PDF должен собираться на любом компьютере без интернета, Google Fonts и системных шрифтов.

Шрифты — только из папки скилла, логотип — по пути из `brand.yaml`:

| Роль | Путь |
|---|---|
| Логотип | `logo.path` в `brand.yaml` |
| Montserrat | `assets/fonts/montserrat/` |
| Geist | `assets/fonts/geist-sans/` |
| Geist Mono | `assets/fonts/geist-mono/` |

Основная команда генерации HTML:

```bash
uv run <SKILL>/scripts/build_html.py \
  lead-magnet-projects/[slug]/content.md \
  -o lead-magnet-projects/[slug]/output/[slug].html
```

## Цвета

| Роль | HEX |
|---|---|
| Primary / логотип / активные элементы | `#3785e2` |
| Soft accent / ссылки / подсветки | `#4ba7f9` |
| Gray wash / фон блоков | `#f5f9fc` |
| Text | `#000000` |
| Surface | `#ffffff` |
| Soft alert | `#f4675d` |

Синий — акцент, не основной цвет текста. Основной текст всегда чёрный.

## Типографика

Утверждённый стиль для новых PDF:

| Элемент | Шрифт | Размер | Жирность | Межстрочный |
|---|---:|---:|---:|---:|
| H1 обложки | Montserrat | `54px` | `800` | `.98` |
| H2 раздела | Montserrat | `40px` | `800` | `1.05` |
| H3 | Montserrat | `25px` | `750` | `1.18` |
| H4 | Geist | `18px` | `700` | `1.28` |
| Body | Geist | `16.5px` | `400` | `1.64` |
| Таблицы | Geist | `14px` | `400/700` | normal |
| Prompt/code | Geist Mono | `14px` | `400/600` | `1.58` |

Montserrat используется для сильного editorial-эффекта в H1/H2/H3. Geist остаётся основным шрифтом для длинного чтения.

## Обложка

Обложка должна быть простой:

- синий фон `#3785e2`;
- логотип в белой плашке;
- крупный короткий H1;
- подзаголовок с объяснением пользы;
- без списка разделов и без текста вроде «практический материал».

Если исходный H1 слишком длинный, делай короткий `--cover-title`, а остальное переноси в `--cover-subtitle`.

## Содержание

Содержание идёт отдельной страницей после обложки:

- заголовок `Содержание`;
- без дополнительной верхней строки с названием бренда, потому что бренд уже есть в колонтитуле;
- крупные номера `01`, `02`, `03`;
- названия только основных `h2`-разделов;
- ссылки на страницы через `target-counter`.

## Контентные страницы

- Каждый `h2` получает eyebrow `Раздел / 01` и мощную чёрную линию под заголовком.
- Основной текст держать в комфортной колонке, не растягивать на всю ширину без необходимости.
- Таблицы, скриншоты, callout-блоки и prompt/code-блоки не должны разрываться посередине страницы.
- Prompt/code-блоки делать тёмными, но не мельчить текст.

## Пагинация и переносы

- Не начинать каждый `h2` с новой страницы по умолчанию: это создаёт пустые страницы и одинокие строки.
- Принудительный перенос перед разделом использовать только для крупных смысловых частей: новая глава, каталог, финальный CTA.
- Заголовки и eyebrow держать со следующим блоком: `break-after: avoid-page`.
- Абзацы и пункты списков защищать от одиноких строк: `widows: 3`, `orphans: 3`.
- Цельные блоки защищать от внутренних разрывов: `break-inside: avoid-page` для `figure`, `table`, `blockquote`, `.callout`, `.prompt-box`.
- Итоговые строки карточек, например `Сложность клонирования...`, помечать как `.difficulty-line`: компактный размер, `break-before: avoid-page`, без большого нижнего отступа.
- Финальный CTA-раздел (заголовок из `cta.platform_heading_prefix`) генератор помечает как `.platform-heading` и переносит на новую страницу: последняя страница должна выглядеть как намеренная CTA-страница.
- Финальную CTA-ссылку (заголовок из `cta.link_heading_prefix`) генератор помечает как `.cta-link-heading`, чтобы она держалась с CTA-текстом.
- После сборки PDF обязательно запускать `scripts/qa_pdf.py`: он ловит страницы, где хвостовой блок или 1-2 строки оказались перед новым разделом.
- Если после автосборки на странице остаётся одно предложение, не лечить это глобальным переносом всех разделов. Править локально: сократить/расширить текст, перенести скриншот, добавить полезный callout или слегка изменить вертикальные отступы.
- Неровный низ страницы допустим, если это помогает избежать оторванного заголовка или одинокой строки. Пустота больше 35-40% страницы — повод для ручной правки.

## Сжатие PDF

- Финальный PDF сжимать локально через `scripts/compress_pdf.py`, не через онлайн-сервисы.
- Стандарт для мобильного/экранного чтения: `160 dpi`, `JPEGQ=84`.
- Сырой PDF, PNG-рендеры QA и тестовые варианты сжатия хранить только в `output/.tmp/`.
- В `output/` оставлять один финальный сжатый PDF и утверждённый HTML.
- После сжатия проверить, что количество страниц, кликабельные ссылки и QA-отчёт не изменились критично.

## Нумерация страниц

- В верхнем колонтитуле не показывать номер страницы.
- В нижнем правом углу использовать только один формат: `стр. X из Y`.
- В содержании `стр. X` означает страницу, на которой начинается раздел.
- Синие номера `01`, `02`, `03` в содержании — это номера пунктов содержания, не страницы.
- Eyebrow `Раздел / 01` — это номер смыслового раздела, не номер страницы.

## Изображения

В `content.md` можно вставлять локальные картинки стандартным Markdown-синтаксисом:

```markdown
![Подпись под изображением](assets/screenshots/example.png "https://example.com")
```

Генератор:

- ищет путь относительно папки проекта;
- встраивает изображение в HTML как `data URI`;
- превращает одиночную картинку в `<figure>`;
- использует title в кавычках как адрес в browser-frame;
- показывает alt-текст как подпись только если title не задан;
- ограничивает высоту, чтобы скриншоты не ломали страницу PDF.

Для скриншотов сайтов использовать `assets/screenshots/`. Для AI-иллюстраций использовать `assets/illustrations/`. Пути — **относительно папки проекта** (`lead-magnet-projects/[slug]/assets/…`), не папки скила: в скиле лежат только бренд-ассеты (`assets/brand/`, `assets/fonts/`).

Стандартный desktop-скриншот для PDF: `1440×760`, без `fullPage`. Такой кадр влезает в browser-frame, не создаёт лишнюю высоту и делает все примеры одинаковыми.

Browser-frame стиль:

- macOS-кнопки слева;
- адресная строка по центру, адрес берётся из Markdown title;
- внешняя рамка `#c9d7e3`;
- шапка `linear-gradient(#e7eef5, #d6e2ec)`;
- нижняя линия шапки `#c8d6e2`;
- адресная строка: фон `rgba(255,255,255,.88)`, рамка `#c2cfdb`, текст `#425466`;
- если title задан, подпись под скриншотом не показывать.

## QA

Перед отдачей пользователю проверить:

- обложка не повторяет содержание;
- логотип не обрезан и не сдвинут;
- изображения вставлены, не обрезаны и имеют понятные подписи;
- нет заголовков, оторванных от первого абзаца;
- нет одиноких 1-2 строк абзаца сверху или снизу страницы;
- нет страниц, где осталась только одна короткая строка/фраза;
- строки `Сложность клонирования...` не висят одни вверху страницы;
- финальный CTA-раздел не разрезан между страницами;
- финальная CTA-ссылка держится с CTA-текстом;
- кириллица рендерится корректно;
- H2/H3 выглядят крупно и жирно;
- body-текст читается с телефона без постоянного зума;
- ссылки кликабельны;
- PDF собран из HTML, а не напрямую из Markdown.
