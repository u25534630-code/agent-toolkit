# Приём нового скилла

Пользователь присылает скилл. Задача: не ставить дубли, не ставить вслепую, не забывать про инструкцию.

Порядок жёсткий. Пропуск шага 1 приводит к дублям, пропуск шага 2 к запуску чужого кода вслепую, пропуск шага 4 к скиллу, о котором через неделю никто не вспомнит.

## Шаг 1. Проверка на дубль

Сравни с тем, что уже стоит. Источники правды:

```bash
ls .claude/skills                      # что установлено
python3 -c "import json; d=json.load(open('skills-lock.json')); print(len(d['skills']))"
grep -rh '^name:' .claude/skills/*/SKILL.md
```

Плюс встроенные скиллы Claude Code и включённые плагины (`claude plugin list`), они тоже считаются.

Исходов три, и озвучивать надо именно тот, который есть:

**Точное совпадение.** Такое имя уже занято, либо это тот же самый скилл из того же источника. Не ставим. Скажи, где он уже лежит, и предложи сверить версии, если источник обновился.

**Функциональный дубль.** Имя другое, работа та же. Не решай сам: покажи, чем перекрывается, назови разницу, если она есть, и дай пользователю выбрать. Совпадение темы при разном механизме дублем не считается. Пример: скилл-советчик про штампы и хук, блокирующий запись, это разные вещи, обоим есть место.

**Нового нет.** Переходи к шагу 2.

## Шаг 2. Осмотр до установки

Склонируй во временную папку и посмотри своими глазами. Отчитайся коротко по четырём пунктам:

- **Объём.** Сколько файлов, сколько весит.
- **Что внутри.** Только Markdown или есть исполняемый код. Скрипты перечисли по назначению.
- **Хуки.** Есть ли `hooks.json`. Хуки работают постоянно, а не по вызову, поэтому их наличие называй всегда.
- **Внешние зависимости.** Нужен ли ключ, Docker, доступ к домену. Домены проверяй на достижимость, часть закрыта политикой окружения.

Если внутри исполняемый код, это не повод отказывать, но повод сказать об этом прямо.

## Шаг 3. Установка

Ставим в `agent-toolkit`, не в проект пользователя.

Способ по обстоятельствам:

```bash
npx -y skills@latest add <ссылка> -y --skill '*'
```

Флаг `--full-depth` нужен, когда в корне репозитория лежит свой `SKILL.md`, иначе установщик возьмёт только его. Список доступных скиллов до установки: тот же вызов с `-l`.

Если у проекта есть собственный установщик, пользуйся им, а не копируй файлы руками.

Когда путь установки прописан в самом скилле (`allowed-tools` со ссылкой на `.claude/skills/имя/scripts/`), клади именно туда, иначе он не запустится.

**Сразу после установки проставь спящий режим.** Вписывай строку `disable-model-invocation: true` в блок frontmatter, перед закрывающим `---`. Вставка именно перед закрывающей чертой безопасна для многострочных описаний, а дописывание в конец файла или в середину блока их ломает.

Исключение делай, только если скилл должен срабатывать сам, и скажи об этом вслух.

После правки проверь, что YAML цел:

```bash
python3 -c "
import re, yaml, pathlib
f = pathlib.Path('.claude/skills/ИМЯ/SKILL.md')
m = re.match(r'^---\n(.*?\n)---\n', f.read_text(), re.S)
print(yaml.safe_load(m.group(1)))
"
```

## Шаг 4. Строка в инструкцию

Открой `SKILLS.md` и добавь строку в таблицу «Шпаргалка». Формат: слева задача человеческим языком, справа команда.

| Что нужно | Что напечатать |
|---|---|
| Понятная задача, а не название скилла | `/имя` |

Слева пиши то, с чем пользователь придёт, а не то, как называется инструмент. «Поднять конверсию страницы», а не «CRO-аудит».

Если скилл требует ключ или не работает в облачной сессии, добавь его и в таблицу ограничений внизу файла.

## Шаг 5. Коммит

Один коммит на скилл. В сообщении: что за скилл, откуда, что внутри необычного, почему оставлен спящим или активным.

Тип коммита обязателен: `feat`, `fix`, `refactor`, `docs`, `style`, `test`, `build`.

## Чего не делать

- **Не ставить наборами впрок.** Скилл, поставленный на всякий случай, не вызывается ни разу. Ставим то, для чего была задача.
- **Не решать за пользователя в спорном случае.** Функциональный дубль это его выбор, а не твой.
- **Не молчать про хуки и скрипты.** Пользователь должен знать, что именно он пускает в свой репозиторий.
- **Не забывать шаг 4.** Скилл без строки в шпаргалке существует только в истории git.
