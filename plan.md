# План реализации

Этапы упорядочены так, чтобы после каждого система была работоспособна и
приносила пользу, даже если следующий этап не сделан.

## Этап 0 — Подготовка доступов (на вашей стороне)

Без этого код работать не будет. Оценка: полчаса.

- [ ] **Битрикс.** Создать входящий вебхук: *Разработчикам → Другое →
      Входящий вебхук*, права `crm`, `user`, `im`. Скопировать URL вида
      `https://bitrix.lovekuhnya.online/rest/1/xxxxxxxx/`.
- [ ] **hh.ru.** Зарегистрировать приложение на `dev.hh.ru`, получить
      `client_id` / `client_secret`, авторизоваться под аккаунтом работодателя,
      сохранить `access_token` и `refresh_token`. Узнать `employer_id`.
- [ ] **Telegram.** Создать бота через `@BotFather`, взять токен. Узнать свой
      `user_id` (через `@userinfobot`).
- [ ] **Google.** Создать сервисный аккаунт в Google Cloud, включить
      Sheets API, скачать JSON-ключ, **расшарить таблицу на e-mail сервисного
      аккаунта** с правами редактора.
- [ ] **Anthropic.** Ключ API для `claude-opus-5`.

Всё складывается в `backend/.env` по образцу `backend/.env.example`.

## Этап 2 — Настройка Битрикса

- [ ] Прогнать `scripts/setup_bitrix.py` — создаст пользовательские поля
      (`UF_CRM_RESUME_URL`, `UF_CRM_AGE`, …) и напечатает их коды.
- [ ] Создать стадии лида под подбор, вписать их коды в `.env`.
- [ ] Руками скрыть лишние поля в форме карточки (инструкция в
      `docs/bitrix_setup.md`).
- [ ] Отключить роботов и БП на воронке подбора, чтобы не было дублей.

## Этап 3 — Обкатка на реальных данных

- [ ] Прогнать поллинг откликов в режиме `DRY_RUN=true` — посмотреть, что
      именно бот собирается писать в Битрикс, ничего не записывая.
- [ ] Сверить маппинг колонок Google-таблицы: бот при старте печатает, какие
      заголовки нашёл, а какие нет.
- [ ] Прогнать 10–15 голосовых команд, посмотреть на распознавание фамилий.
      Русские фамилии — слабое место STT; если ошибается, добавить в
      `initial_prompt` whisper список фамилий активных кандидатов.
- [ ] Включить запись, снять `DRY_RUN`.

Бот закрывает 90% работы, но для разбора и отчётности удобен экран:

- [ ] Telegram Mini App: список активных кандидатов, карточка, быстрые

- [ ] Дашборд: воронка за период, конверсия отклик → звонок → собес → стажёр,

Стек: React + TypeScript + Tailwind, данные — REST из FastAPI
(`/api/candidates`, `/api/stats`). Пишется с Claude Sonnet 5.

## Этап 6 — Эксплуатация

- [ ] Бэкап БД раз в сутки.

      какой интервал напоминать.
