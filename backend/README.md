# Бэкенд

Один процесс: FastAPI (health-check и REST для фронтенда), Telegram-бот на
aiogram и планировщик APScheduler.

**Python 3.11–3.13.** На 3.14 и новее пока нет колёс `ctranslate2`, на котором
работает `faster-whisper`, — установка упадёт на сборке из исходников.

## Запуск

Проще всего — скриптом, он сам создаст окружение, поставит зависимости и
при первом запуске позовёт мастер настройки:

```bash
./start.sh          # macOS, Linux
start.bat           # Windows
```

Пошаговая инструкция для нетехнического пользователя:
[docs/quickstart_windows.md](../docs/quickstart_windows.md).

Вручную:

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python -m scripts.setup_env      # мастер создаст .env
# либо cp .env.example .env и заполнить руками

uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Бот стартует вместе с приложением, отдельно запускать не нужно.

Первый запуск скачивает модель whisper (`medium` — около 1.5 ГБ). Если сервер
слабый, поставьте `WHISPER_MODEL=small`: качество на русском заметно ниже, но
для коротких реплик обычно хватает.

## Проверка настроек

```bash
./check.sh          # macOS, Linux
check.bat           # Windows
python -m scripts.check
```

Читает `.env` и по очереди стучится в Телеграм, Anthropic, Google-таблицу,
Битрикс и hh.ru: ничего не меняет и никуда не пишет, но по каждому сервису
говорит, работает он, не подключён или сломан — и что именно сделать. Отдельно
от старта приложения намеренно: при старте важно подняться даже с половиной
настроек, здесь наоборот — подробно сказать, чего не хватает.

Рядом лежит `stages.bat` — то же самое для `scripts/setup_bitrix --show-stages`:
печатает воронки и коды стадий, чтобы заполнить `BITRIX_DEAL_CATEGORY_ID`.

## Обновление

`update.bat` (Windows) скачивает ветку архивом и заменяет файлы программы,
исключая `.env`, `service-account.json`, базу и `.venv`. Себя не перезаписывает:
cmd читает батник по мере выполнения, и подмена работающего файла уводит
интерпретатор в мусор.

## Сначала — вхолостую

Пока не уверены в настройках, поставьте в `.env`:

```
DRY_RUN=true
```

Бот будет работать полностью, но вместо записи в Битрикс и таблицу — писать в
лог, что собирался сделать. Удобно, чтобы проверить маппинг стадий и колонок,
ничего не испортив.

## Что можно не подключать

Каждая интеграция включается своей настройкой в `.env` и отключается пустым
значением. Бот стартует в любом случае и пишет в лог, что именно выключено.

| Пусто | Что перестаёт работать | Что продолжает |
|---|---|---|
| `BITRIX_WEBHOOK_URL` | сделки и стадии в CRM | всё остальное |
| `GOOGLE_SPREADSHEET_ID` | обе вкладки таблицы | всё остальное |
| `HH_ACCESS_TOKEN` | автоматический приём откликов | ручной ввод кандидатов |
| `ANTHROPIC_API_KEY` | разбор команд моделью | разбор правилами, бесплатно |

Обязателен только `TELEGRAM_BOT_TOKEN` — без него нет самого бота.

**Разбор команд без Anthropic.** Если ключа нет (например, нечем оплатить —
российские карты там не принимают), команды разбираются по ключевым словам:
`app/integrations/rules.py`. Точность ниже на вольных формулировках, но
типовые реплики «Фамилия, что произошло» покрыты, включая даты вида
«в четверг в 15:00» и «12 августа». Появится ключ — впишите его в `.env`,
и разбор переключится на модель сам.

## Подготовка Битрикса

```bash
# посмотреть коды стадий вашей воронки и вписать их в .env
python -m scripts.setup_bitrix --show-stages

# создать пользовательские поля в карточке сделки
python -m scripts.setup_bitrix --create-fields
```

Скрипт ничего не удаляет: существующие поля пропускаются. Что скрыть в карточке
руками — в `../docs/bitrix_setup.md`.

## Структура

```
app/
  config.py            все настройки, единственное место чтения .env
  deps.py              сборка клиентов внешних систем
  main.py              FastAPI + запуск бота и планировщика
  scheduler.py         поллинг откликов, напоминания, вечерний отчёт
  db/
    models.py          Candidate, Reminder, CallLog, PendingAction
    session.py         движок и сессии
  integrations/
    bitrix.py          Bitrix24 REST через входящий вебхук
    hh.py              hh.ru: отклики и резюме, авто-обновление токена
    sheets.py          Google Sheets с маппингом колонок по заголовкам
    claude.py          разбор реплики в команду, claude-opus-5
    stt.py             faster-whisper, распознавание голосовых
  services/
    candidates.py      доменная логика: что делать при каждом действии
    reminders.py       напоминания
    reports.py         дневная сводка
  bot/
    main.py            экземпляр бота и диспетчера
    handlers.py        голос, текст, кнопки, команды
    keyboards.py       клавиатуры
scripts/
  setup_env.py         мастер: задаёт вопросы и создаёт .env
  check.py             проверка: что подключено, что нет, что не работает
  cleanup_deals.py     разбор завала: старые сделки стадии — в другую стадию
  setup_bitrix.py      воронки, стадии и пользовательские поля сделок
  hh_auth.py           авторизация работодателя на hh.ru
```

## Как это работает

**Отклик → сделка.** Планировщик раз в 15 минут дёргает
`/negotiations/response`, по каждому новому отклику берёт полное резюме, ищет
контакт по телефону и заводит сделку в воронке HR. Ключ идемпотентности —
`hh_negotiation_id`, повторный поллинг дублей не создаёт.

**Реплика → действие.** Голосовое расшифровывается локально, текст уходит в
`claude-opus-5` со structured outputs и возвращается разобранной командой.
Кандидат ищется по нормализованному имени среди активных; если подходит
несколько — бот спрашивает кнопками. До нажатия «Да, выполнить» во внешние
системы ничего не пишется.

**Напоминания** живут в БД, а не только в планировщике: перезапуск процесса не
теряет напоминание о завтрашнем собеседовании.

## Проверка

```bash
curl localhost:8000/health
```

Покажет, включены ли hh.ru и Google Sheets и стоит ли `DRY_RUN`.

## API для фронтенда

| Метод | Что отдаёт |
|---|---|
| `GET /health` | состояние интеграций |
| `GET /api/candidates?status=&limit=` | список кандидатов |
| `GET /api/stats/daily?day=YYYY-MM-DD` | сводка за день |

## Известные ограничения

- **Токен hh.ru** живёт две недели. Клиент обновляет его сам по
  `refresh_token`, но новое значение в `.env` не пишет — после перезапуска
  обновление произойдёт заново. Если процесс перезапускается часто, впишите
  свежие токены в `.env` руками (в логах будет предупреждение).
- **Распознавание русских фамилий** — слабое место whisper. Фамилии активных
  кандидатов подставляются подсказкой, это заметно помогает, но при ошибке
  бот просто не найдёт кандидата и переспросит — испортить данные не сможет.
- **SQLite** держит нагрузку одного рекрутера с запасом. При нескольких
  пользователях и десятках тысяч кандидатов переключите `DATABASE_URL` на
  PostgreSQL — код менять не нужно.
